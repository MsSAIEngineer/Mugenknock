# MLA を新版 MLA-C02 に合わせる

- 状態: 実装中
- 起票日: 2026-11-01

## なぜやるか

MLA は 2026-09-29 から新版 **MLA-C02** で実施されている（MLA-C01 は 2026-09-28 まで）。
アプリは試験コード・配点・ドメイン名・問題生成の指示がすべて C01 のままで、生成の指示に「Bedrock は避ける」と書いてあった。
その結果、MLA の 349 問は SageMaker に偏り（94% の問題に登場・59% の問題で正解に入る）、C02 で大量に追加された
生成 AI の範囲（Bedrock・RAG・ナレッジベース・エージェント・評価・Guardrails 等）が**ほぼ 0 問**になっている。
受験者は新版の約 1/3 を占める範囲を演習できない。

試験ガイドの自動更新（`refresh-exam-guide.sh`）は 10/28 に MLA を更新していたが、版の変化を拾えなかった
（日本語の資格紹介ページを読んでおり、版の番号の変化を検出する仕組みも無い）。

## 何を作るか

1. MLA の試験情報を C02 にする。試験コード MLA-C02、配点 28/24/24/24、ドメイン名は公式の日本語名
   （ML と AI のためのデータの準備／ML モデルと基盤モデル (FM) の開発／ML と AI のワークフローのデプロイとオーケストレーション／
   ML と AI のソリューションの運用、モニタリング、保護）。
2. MLA の問題生成の指示を C02 の公式タスクに合わせる。Bedrock を避ける指示を外し、C02 で追加された範囲を優先させ、
   C02 で外れた範囲（SageMaker Neo・BYOC・モデル軽量化・学習リソースへの EFS/FSx 読み込み・EventBridge によるインフラ監視）と
   対象外サービスを出さないようにする。
3. 生成 AI 範囲の問題を足す。第1弾は手動で約 100 問を生成・検証する（全体の約 2 割）。以後は通常の生成で
   C02 の追加範囲が優先されるようにし、目安として全体の 3 割台まで増やす。
4. 試験ガイドの自動更新が、版の変化（例: C01→C02）を検出して知らせるようにする。

## 受入条件

- [ ] 画面（資格選択・資格ダッシュボード・模試）に MLA-C02 と C02 のドメイン名・配点が出る
- [ ] 予想スコアが C02 の配点（28/24/24/24）で計算される
- [ ] `instructions/MLA.txt` が C02 の4ドメイン・全タスクを含み、Bedrock を避ける指示が無い
- [ ] 生成(01)・検証(02)・通報チェック(03)・レポート(99)のドメイン名が C02 に揃っている（examDomains.json と一致）
- [ ] 生成 AI 範囲（Bedrock・RAG・エージェント・評価・Guardrails・ベクトル DB 等）が正解に入る MLA 問題が 80 問以上ある（検証済み・公開中）
- [ ] `refresh-exam-guide.sh` が公式の試験ガイド一覧から現行の試験コードを取り、マスタと違えば知らせる

## 対象外（やらないこと）

- SAP-C03（2026-10-27 申込開始・C02 は 11/16 まで）と DVA-C03（12/1 申込開始・C02 は 11/30 まで）の対応。別 spec で行う
- C02 で外れた範囲・対象外サービスを含む既存 MLA 問題（約 25 問）の整理。今回は生成の指示で新規に作らないようにするだけ
- 英語版
- 既存ユーザーの過去の予想スコア履歴の再計算（配点が変わるので新しい記録から C02 の配点になる）

## 影響範囲

| 種別 | 影響 |
|---|---|
| 画面 | 資格選択・資格ダッシュボード・ホームのドメイン表示・予想スコア（配点）・模試 |
| API | なし（Lambda は examDomains.json の名前を使うため、同梱し直しのデプロイが要る） |
| DynamoDB | MLA の問題を約 100 問追加（Questions は本番と共通）。既存データの変更なし（ドメインは番号で持つ） |
| 夜間バッチ | `instructions/MLA.txt`、01/02/03/99 のドメイン名、`refresh-exam-guide.sh` |
| デプロイ | フロント＋**Lambda も要デプロイ（dev+prod）** |

## 既存の不変条件との整合

- 出題プールの条件 `!isHidden && !!validityCheckedAt` を維持するか: はい（追加問題も検証(02)を通してから出る）
- ドメイン均等化（deficit round-robin）の方針に反しないか: 反しない（ドメインの番号は C01 と C02 で同じ並び）
- ゲスト/ログイン境界に反しないか: 反しない
- `correctAnswerIndices` を正準とする不変条件に触れるか: 触れない
