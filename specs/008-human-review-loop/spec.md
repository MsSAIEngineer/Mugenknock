# 008 人の確認の経路（AI の判断を人が確かめる）— 仕様

出典: `docs/10-ops-review.md` 4.1〜4.4（2026-10-27 の運営レビュー）。本人指示「優先度 S・A は全て対応」（2026-10-28）。

## 背景

生成と検証が同じモデルで、検証の確かさを誰も測っていない。検証が正解を変えた11問が人の確認なしで出題中。
監査の指摘26問が2か月以上手つかず。生成指示の自動改良に、良くなったかの確認がない。

## 受入条件

- [x] 検証（02）が**正解の位置を変える**修正は自動で反映されず、修正案として残り、問題は非表示になる
- [x] 検証（02）の**削除提案**は問題を消さず、非表示にして人の確認に回す
- [x] 管理画面「スキャン結果」に「人の確認待ち」があり、修正案の適用／却下、問題なし／誤りありを記録できる
- [x] 28日ごとに20問を無作為に抜き取って確認待ちに入れる（半分は直近30日に作成・修正された問題）
- [x] 2026-10-27 以前に AI が正解を変えた問題を、一度だけ確認待ちに入れられる
- [x] 日次レポートに、確認待ちの件数と一番古い日付・監査指摘・通報・抜き取りの不良率・生成指示の変更が出る
- [x] 監査 `-i` の生成指示の改良は、既定で提案のみ（書き換えない）
- [x] 確認待ちはゲストに無関係（管理者 API・管理画面のみ）

## 対象外

- 別系統のモデルによる独立判定（必要になったら足す）
- 監査指摘（`auditNote`）の処理画面の作り直し（既存の「監査指摘あり」で扱う）
