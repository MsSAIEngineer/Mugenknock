## 整理後の構成

| 画面 | 役割 | 中身 |
|---|---|---|
| ホーム `/aws/` | 今の実力と今日やること | 実力の現在地・予想スコアの推移（現状のまま）・目標演習量・日めくり・苦手分析の要約カード（遷移先を記録へ） |
| 記録 `/aws/stats`（旧「統計・分析」） | 過去の記録すべて | タブ: **苦手分析** / **解答履歴** / **正答率の推移** / **演習量** |
| マイページ `/aws/mypage` | 自分の設定 | 目標資格・学習目標・週間達成・取得済資格（タブをなくして1ページに） |

### 記録のタブ

| タブ | 中身 | 出どころ |
|---|---|---|
| 苦手分析（既定） | 苦手ドメイン（窓: 直近10 / 20 / 30問 / **累計**）・間違えやすい問題・問題詳細モーダル | マイページ苦手分析タブを移設。統計「ノック成績」のドメイン別正答率（累計）は窓の「累計」に統合 |
| 解答履歴 | セッション一覧（展開で問題別の正誤・ブックマーク操作） | 統計「ノック履歴」をそのまま。マイページ履歴タブ（直近10件）は廃止 |
| 正答率の推移 | セッションごとの正答率チャート・模試の合否 | 統計「ノック成績」の成績推移 |
| 演習量 | 解いた問題数／総数・日次の演習量 | 統計「ノック量」 |

### ホームの「推移と記録」を残す理由（spec の未決事項への回答）

ホームの推移は **予想スコア** の推移（`scoreHistData_*` に保存。ホームだけが記録している）で、
記録画面の推移は **セッションごとの正答率**。指標が違うので同じグラフの重複ではない。
予想スコアの推移を記録へ移すには、`CombinedDetailModal`（ホーム内の約600行と、統計同期を待って記録する仕組み）を
切り出す必要があり、2026-10-20 に直したばかりの記録ルールを壊す危険が大きい。
そこで**ホームに残し、名前で区別する**:「推移と記録」→「予想スコアの推移」、記録の「成績推移」→「正答率の推移」。

## アプローチ

### 採用案
1. マイページの苦手分析タブを `src/components/records/WeakAnalysis.tsx` に切り出す（データ取得・状態・問題詳細モーダルごと）。
   記録画面の苦手分析タブはこのコンポーネントを置くだけにする。窓の選択肢に「累計」を足す。
2. 統計画面を「記録」に改名し、タブを上の4つに組み替える。旧ドメイン別正答率（累計）の表示は削除（苦手分析の「累計」に統合）。
3. マイページからタブを外す。履歴タブにあった取得済資格は目標の下へ移す。履歴のセッション一覧は削除。
4. ナビに「記録」を足す。PC サイドバー: ホーム / トレーニング / 記録 / マイページ。スマホ下部タブも同じ4つ（4つまでは幅が足りる）。
5. 遷移の付け替え:
   - ホーム苦手分析カード → `navigate('/aws/stats', { state: { tab: 'analysis' } })`
   - 模試設定「ノック成績 →」→ `/aws/stats`（`tab: 'trend'`）。表示名は「正答率の推移 →」
   - マイページに `location.state.tab` が `'analysis' | 'history'` で来たら（古いリンク・古い JS）、`/aws/stats` の該当タブへ `replace` で転送
6. タブ名の改名: 「ノック量／ノック成績／ノック履歴」→「演習量／正答率の推移／解答履歴」。ヒントバナー（`stats.hint`）も書き直す。

### 却下した案

| 案 | 却下理由 |
|---|---|
| 予想スコアの推移も記録へ移す | 上記「ホームの推移を残す理由」。記録ルールの作り直しが必要で危険が大きく、指標も違う |
| 新しい `/aws/records` を作り、`/aws/stats` を転送 | URL を変える利点が小さい。既存ブックマーク・e2e・パンくずの変更が増える |
| マイページのタブを残して中身だけ減らす | 1タブしか残らず、タブの意味がない |
