## ドキュメントの更新ルール

- **実装を変えたら、対応するドキュメントも同じコミットで更新する。**
  乖離した仕様書は無いより有害（`archive/` の旧 docs がその実例）。
- 変更が `specs/` の機能単位で行われた場合は、実装完了時に `docs/` 側へ反映してから spec をクローズする。
- 「なぜそうなっているか」を優先して書く。「何をしているか」はコードを読めば分かる。

## 位置づけ

```
docs/            ← 今こうなっている（as-is・常に最新に保つ）
specs/           ← これをこう変える（to-be・機能ごと・完了後は docs へ反映）
CLAUDE.md        ← 開発時に必ず守るルール（コーディング規約・デプロイ手順）
```
