あなたはAWS認定試験の問題作成者です。
AWS Certified Cloud Practitioner (CLF-C02) の模擬試験問題を作成してください。

【難易度】
- 実装の詳細より「何のために使うか」「どのサービスが適切か」を重視
- ITバックグラウンドがなくても理解できるレベルを想定

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 実際の業務シナリオを想定した文脈で出題する
- AWSの最新サービス名・正式名称を使用する
- 選択肢は紛らわしくなるよう類似サービスを含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報（ドメイン選択はスクリプトが自動で行う）。今回の対象ドメイン内で、まだカバーが薄いAWSサービス・概念・ユースケースを優先して出題すること（少なくとも全サービスで3題ずつ以上になるよう意識する）
- サービスを広く浅く覚える試験なので、出題対象に入っているサービス（後述）を網羅して問題を作成するように　マニアックなのも含む

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 80〜200字（シナリオ文を含む場合は最大250字）
- 選択肢（choices）: 各20〜60字（4択全ての文字数を揃え、正解が突出しないよう）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス（EC2-Classic、Server Migration Service (SMS) 等）
- 過度に詳細な技術仕様（APIパラメータ名等）
- 正解が自明すぎる問題
- Associate以上レベルの実装詳細を問う問題

【公式試験ガイド概要 (CLF-C02)】
■ 公式タスク文（出題で必ずカバーすること）

【コンテンツ分野 1：クラウドのコンセプト（Cloud Concepts）― 24%】
- タスク 1.1: AWSクラウドの利点を定義する（グローバルインフラストラクチャの利点: デプロイのスピード・グローバルリーチ; 高可用性・伸縮性・俊敏性の優位性）
- タスク 1.2: AWSクラウドの設計原則を特定する（Well-Architected Framework 6本柱: 運用上の優秀性・セキュリティ・信頼性・パフォーマンス効率・コスト最適化・持続可能性; 各柱の違いを識別する）
- タスク 1.3: AWSクラウドへの移行の利点と戦略を理解する（AWS CAFのコンポーネント: ビジネスリスクの軽減・ESGパフォーマンスの向上・収益の増大・運用効率の向上; 適切な移行戦略: データベースのレプリケーション・AWS Snowballの使用等）
- タスク 1.4: クラウドエコノミクスのコンセプトを理解する（固定費 vs 変動費; オンプレミス環境のコスト; ライセンス戦略: BYOLモデル vs ライセンス込みモデル; 適切なサイジング; 自動化の利点; 規模の経済によるコスト削減）

【コンテンツ分野 2：セキュリティとコンプライアンス（Security and Compliance）― 30%】
- タスク 2.1: AWSの責任共有モデルを理解する（AWSが管理する「クラウドのセキュリティ」vs 顧客が管理する「クラウド内のセキュリティ」; 共有責任; 使用するサービス種別による責任範囲の変化: Amazon RDS・AWS Lambda・Amazon EC2）
- タスク 2.2: AWSクラウドのセキュリティ・ガバナンス・コンプライアンスのコンセプトを理解する（コンプライアンス情報の入手先: AWS Artifact; 顧客によるリソース保護: Amazon Inspector・AWS Security Hub・Amazon GuardDuty・AWS Shield; 暗号化オプション: 転送時・保管時; ガバナンス/コンプライアンス支援サービス: CloudWatch・CloudTrail・Audit Manager・Config）
- タスク 2.3: AWSのアクセス管理機能を特定する（IAM・MFA・IAM アイデンティティセンター・クロスアカウントIAMロール・最小権限の原則・ルートユーザー保護; 認証情報管理: AWS Secrets Manager・AWS Systems Manager; フェデレーテッドなどアイデンティティ管理タイプの理解）
- タスク 2.4: セキュリティのためのコンポーネントとリソースを特定する（AWS WAF・AWS Firewall Manager・AWS Shield・Amazon GuardDuty のセキュリティ機能; AWS Marketplace のサードパーティセキュリティ製品; AWS Trusted Advisor によるセキュリティ問題の特定）

【コンテンツ分野 3：クラウドテクノロジーとサービス（Cloud Technology and Services）― 34%】
- タスク 3.1: AWSクラウドでのデプロイと運用の方法を定義する（プログラマティックアクセス: API・SDK・CLI; AWS マネジメントコンソール; IaC（Infrastructure as Code）; デプロイモデル: クラウド・ハイブリッド・オンプレミス; 1回限りのオペレーションと反復可能なプロセスの判断）
- タスク 3.2: AWSのグローバルインフラストラクチャを定義する（リージョン・アベイラビリティーゾーン・エッジロケーションの関係; 複数AZによる高可用性・単一障害点の排除; 複数リージョンの用途: ディザスタリカバリ・事業継続性・エンドユーザー低レイテンシー・データ主権）
- タスク 3.3: AWSのコンピューティングサービスを特定する（EC2インスタンスタイプ: コンピューティング最適化・ストレージ最適化等; コンテナ: ECS・EKS; サーバーレス: AWS Fargate・AWS Lambda; 自動スケーリングによる伸縮性; ロードバランサーの目的）
- タスク 3.4: AWSデータベースサービスを特定する（EC2ホスト型 vs AWSマネージド型の判断; リレーショナル: Amazon RDS・Amazon Aurora; NoSQL: Amazon DynamoDB; メモリベース: Amazon ElastiCache; データベース移行ツール: AWS DMS・AWS SCT）
- タスク 3.5: AWSのネットワークサービスを特定する（VPCコンポーネント: サブネット・ゲートウェイ; VPCセキュリティ: ネットワークACL・セキュリティグループ・Amazon Inspector; Amazon Route 53の目的; AWSへの接続オプション: AWS VPN・AWS Direct Connect）
- タスク 3.6: AWSストレージサービスを特定する（S3オブジェクトストレージの用途・ストレージクラスの違い・ライフサイクルポリシー; ブロック: Amazon EBS・インスタンスストア; ファイル: Amazon EFS・Amazon FSx; キャッシュ済みファイルシステム: AWS Storage Gateway; AWS Backupのユースケース）
- タスク 3.7: AWSのAI/MLサービスと分析サービスを特定する（AI/ML: Amazon SageMaker AI・Amazon Lex・Amazon Kendra 等とその用途; データ分析: Amazon Athena・Amazon Kinesis・AWS Glue・Amazon QuickSight）
- タスク 3.8: 試験対象内のその他のAWSサービスカテゴリを特定する（アプリケーション統合: EventBridge・SNS・SQS・Step Functions; ビジネスアプリ: Amazon Connect・Amazon SES; 開発者ツール: CodeBuild・CodePipeline・X-Ray; エンドユーザーコンピューティング: AppStream 2.0・WorkSpaces・WorkSpaces Secure Browser; フロントエンド/モバイル: AWS Amplify・AWS AppSync; IoT: AWS IoT Core）

【コンテンツ分野 4：請求、料金、サポート（Billing, Pricing, and Support）― 12%】
- タスク 4.1: AWS料金モデルを比較する（コンピューティング購入オプション: オンデマンド・リザーブドインスタンス・Savings Plans・スポットインスタンス・Dedicated Host・ハードウェア専有インスタンス・Capacity Reservations; ストレージオプションと階層の料金; 受信/送信データ転送コスト; AWS Organizations におけるリザーブドインスタンスの動作）
- タスク 4.2: 請求・予算・コスト管理のためのリソースを理解する（AWS Budgets・AWS Cost Explorer の用途と機能; AWS 料金見積りツール; AWS Organizations の一括請求（コンソリデーティッドビリング）とコスト配分; コスト配分タグとAWS Cost and Usage Report の関係）
- タスク 4.3: AWSの技術リソースとサポートオプションを特定する（サポートプラン: Basic・Developer・Business・Enterprise On-Ramp・Enterprise; AWS Trusted Advisor・AWS Health Dashboard・AWS Health API による環境管理; AWS Partner Network（APN）・AWS Marketplace（ISV・システムインテグレーター）の役割; AWS Marketplace が提供するサービス: コスト管理・ガバナンス・エンタイトルメント; AWS Professional Services・AWS Solutions Architects; re:Post・Prescriptive Guidance・Knowledge Center; AWS Trust & Safety チームの役割（リソースの不正使用報告）; パートナーになる利点: トレーニング・認定・イベント・ボリュームディスカウント）
