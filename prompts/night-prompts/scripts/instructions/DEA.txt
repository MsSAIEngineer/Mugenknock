# EXAM_GUIDE_URL: https://aws.amazon.com/jp/certification/certified-data-engineer-associate/
# LAST_REFRESHED: 2026-10-26


あなたはAWS認定試験の問題作成者です。
AWS Certified Data Engineer – Associate (DEA-C01) の模擬試験問題を作成してください。

【難易度】
- Associate レベル：データパイプライン設計・ETL・データストア管理・データセキュリティの実践的な知識
- AWSのデータサービスを使ったデータエンジニアリングの実務スキルを問う
- Glue・Kinesis・Redshift・Athena の深い理解が必要

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的なデータパイプライン・ETL要件を提示してから問う
- 「最もコスト効率が高い」「最小の運用負荷」「最もスケーラブル」などの条件を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（データ要件・既存構成・パフォーマンス要件を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な設定・アーキテクチャを明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス（例：Kinesis Data Analytics → Amazon Managed Service for Apache Flink が正式名称）
- CLFレベルの単純なサービス説明問題
- 機械学習・AI に関する問題（MLA・AIF の領域）。ただし試験ガイドが明示するLLM統合（データ処理用途）・ベクトルインデックス・Bedrock ナレッジベース（ベクトル化の概念）はデータエンジニアリングの範囲として出題してよい
- 試験対象外サービスを正解・主要選択肢にしない：公式の対象外リストにある Amazon FinSpace・AWS X-Ray・AWS Amplify・AWS AppSync・IoTサービス群（AWS IoT SiteWise 等）・AWS Elastic Beanstalk・AWS App Runner・Amazon SES・Amazon Pinpoint 等。Amazon Timestream は公式の対象サービス一覧に載っていないため同様に扱う

---
【公式試験ガイド概要 (DEA-C01)】

■ 試験概要
- 試験時間130分・65問（採点対象50問＋採点対象外15問）。択一選択（正解1・不正解3）または複数選択（5つ以上の選択肢から正解2つ以上）
- 合格スコア720（100〜1,000の換算スコア）
- 推奨経験：データエンジニアリング2〜3年相当、AWS実務1〜2年以上
- 試験対象外のタスク：MLのトレーニング・推論の実行、プログラミング言語固有の構文知識、データに基づくビジネス上の結論の導出

■ ドメイン配点
- Domain 1: Data Ingestion and Transformation（データの取り込みと変換）— **34%**
- Domain 2: Data Store Management（データストア管理）— **26%**
- Domain 3: Data Operations and Support（データ運用とサポート）— **22%**
- Domain 4: Data Security and Governance（データセキュリティとガバナンス）— **18%**

■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：Data Ingestion and Transformation（34%）】

- **Task 1.1: Perform data ingestion（データ取り込みの実行）**
  - ストリーミングソースからの読み取り：Kinesis・MSK・DynamoDB Streams・DMS・Glue・Redshift
  - バッチソースからの読み取り：S3・Glue・EMR・DMS・Redshift・Lambda・AppFlow、バッチ取り込み用の設定オプション
  - データAPIの利用
  - スケジューラ設定（EventBridge・Apache Airflow・ジョブとクローラーの時間ベースのスケジュール）・イベントトリガー（S3イベント通知・EventBridge）
  - KinesisからLambda関数を呼び出す
  - データソースへの接続を許可するIPアドレスの許可リスト作成
  - スロットリングの実装とレート制限の克服（DynamoDB・RDS・Kinesis）
  - ストリーミングデータ配信のファンイン/ファンアウト
  - データ取り込みパイプラインの再現性（リプレイ可能性）・ステートフル/ステートレスなデータトランザクションの定義

- **Task 1.2: Transform and process data（データの変換と処理）**
  - 要件に基づく変換サービスの実装（EMR・Glue・Lambda・Redshift）
  - フォーマット変換（CSV→Apache Parquet等）・複数ソースからのデータ統合・データ処理のコスト最適化
  - パフォーマンスのためのコンテナ使用の最適化（EKS・ECS）
  - JDBC/ODBCによるさまざまなデータソースへの接続
  - 一般的な変換エラーとパフォーマンス問題のトラブルシューティング・デバッグ
  - 他システムがデータを利用できるデータAPIの作成
  - データのボリューム・速度・多様性（構造化・非構造化）の定義
  - データ処理のための大規模言語モデル（LLM）の統合

- **Task 1.3: Orchestrate data pipelines（データパイプラインのオーケストレーション）**
  - ETLワークフローの構築（Lambda・EventBridge・MWAA・Step Functions・Glueワークフロー）
  - パフォーマンス・可用性・スケーラビリティ・レジリエンス・耐障害性を備えたパイプライン構築
  - サーバーレスワークフローの実装と保守
  - 通知サービスによるアラート送信（SNS・SQS）

- **Task 1.4: Apply programming concepts（プログラミング概念の応用）**
  - コード最適化による取り込み・変換ランタイムの短縮
  - 同時実行性とパフォーマンスのためのLambda関数設定
  - プログラミング言語とフレームワーク（Python・SQL・Scala・R・Java・Bash・PowerShell）
  - ソフトウェアエンジニアリングのベストプラクティス（バージョン管理・テスト・ログ記録・モニタリング）
  - IaCによるデプロイ（CloudFormation・AWS CDK）・AWS SAMによるサーバーレスデータパイプライン（Lambda・Step Functions・DynamoDB）のパッケージ化とデプロイ
  - Lambda関数内からのストレージボリュームのマウントと使用
  - CI/CD（データパイプラインの実装・テスト・デプロイ）・分散コンピューティングの定義
  - データ構造とアルゴリズム（グラフ・ツリー）

【第2ドメイン：Data Store Management（26%）】

- **Task 2.1: Choose a data store（データストアの選択）**
  - コスト・パフォーマンス要件に応じたストレージサービスの実装（Redshift・EMR・Lake Formation・RDS・DynamoDB・Kinesis Data Streams・MSK）
  - アクセスパターンに応じたストレージ設定
  - ユースケース適用：Aurora PostgreSQLでのHNSW等のインデックスアルゴリズム、MemoryDBによるキー値ペアへの高速アクセス
  - 移行ツールの統合（Transfer Family）
  - データ移行・リモートアクセス方法（Redshiftフェデレーテッドクエリ・マテリアライズドビュー・Spectrum）
  - ロック管理によるデータアクセスの制御（Redshift・RDS）
  - オープンテーブルフォーマットの管理（Apache Iceberg）
  - ベクトルインデックスのタイプ（HNSW・IVF）

- **Task 2.2: Understand data cataloging systems（データカタログシステムの理解）**
  - データカタログを使ったデータソースのデータ利用
  - 技術データカタログの構築・参照（Glue Data Catalog・Apache Hive metastore）
  - Glueクローラーによるスキーマ検出とデータカタログへの登録
  - パーティションとデータカタログの同期
  - カタログ用の新しいソース/ターゲット接続の作成（Glue）
  - ビジネスデータカタログの作成・管理（Amazon SageMaker Catalog）

- **Task 2.3: Manage the lifecycle of data（データのライフサイクルの管理）**
  - S3とRedshift間のロード/アンロード操作
  - S3ライフサイクルポリシーによるストレージ階層変更・期限到達データの無効化（有効期限設定）
  - S3バージョニング・DynamoDB TTLの管理
  - ビジネス要件・法的要件を満たすデータ削除
  - 適切なレジリエンスと可用性によるデータ保護

- **Task 2.4: Design data models and schema evolution（データモデルとスキーマ進化の設計）**
  - Redshift・DynamoDB・Lake Formationのスキーマ設計
  - データ特性の変化への対処（スキーマ進化）
  - スキーマ変換（AWS SCT・AWS DMS Schema Conversion）
  - データリネージの確立（SageMaker ML Lineage Tracking・SageMaker Catalog）
  - インデックス・パーティショニング戦略・圧縮等のデータ最適化のベストプラクティス
  - ベクトル化の概念（Amazon Bedrock ナレッジベース）

【第3ドメイン：Data Operations and Support（22%）】

- **Task 3.1: Automate data processing by using AWS services（AWSサービスを使ったデータ処理の自動化）**
  - パイプラインのオーケストレーション（MWAA・Step Functions）・マネージドワークフローのトラブルシューティング
  - SDKによるAWS機能の呼び出し
  - AWSサービス機能によるデータ処理（EMR・Redshift・Glue）
  - データAPIの利用・管理
  - 変換対象データの準備（Glue DataBrew・SageMaker Unified Studio）
  - データのクエリ（Athena）
  - Lambdaによるデータ処理の自動化・イベントとスケジューラの管理（EventBridge）

- **Task 3.2: Analyze data by using AWS services（AWSサービスを使ったデータ分析）**
  - データの可視化（DataBrew・Amazon Quick（旧QuickSight））
  - データの検証・クリーニング（Lambda・Athena・Quick・Jupyter Notebook・SageMaker Data Wrangler）
  - RedshiftとAthenaのSQLによるクエリ・ビュー作成
  - Apache Spark対応Athenaノートブックによるデータ探索
  - プロビジョニング型とサーバーレスのトレードオフ
  - データ集約・移動平均・グループ化・ピボットの定義

- **Task 3.3: Maintain and monitor data pipelines（データパイプラインの保守とモニタリング）**
  - 監査用ログの抽出・監査とトレーサビリティのためのログ記録/モニタリングソリューションのデプロイ
  - モニタリング中の通知によるアラート送信
  - CloudTrailによるAPIコール追跡
  - CloudWatch Logsによるアプリケーションデータのログ記録（設定とオートメーションに重点）
  - ログ分析（Athena・EMR・OpenSearch Service・CloudWatch Logs Insights・ビッグデータアプリケーションログ）
  - パフォーマンス問題のトラブルシューティング・パイプラインのトラブルシューティングとメンテナンス（Glue・EMR）

- **Task 3.4: Ensure data quality（データ品質の確保）**
  - データ処理時のデータ品質チェック（空フィールドのチェック等）
  - データ品質ルールの定義（Glue DataBrew）
  - データ一貫性の調査（Glue DataBrew）
  - データサンプリング手法
  - データスキュー対処メカニズムの実装

【第4ドメイン：Data Security and Governance（18%）】

- **Task 4.1: Apply authentication mechanisms（認証メカニズムの適用）**
  - VPCセキュリティグループの更新
  - IAMグループ・ロール・エンドポイント・サービスの作成/更新
  - パスワード管理用認証情報の作成とローテーション（Secrets Manager）
  - アクセス用IAMロールのセットアップ（Lambda・API Gateway・AWS CLI・CloudFormation）
  - IAMポリシーの適用（S3 Access Points・PrivateLink）
  - マネージドサービスとアンマネージドサービスの違い
  - SageMaker Unified Studio のドメイン・ドメインユニット・プロジェクトの使用

- **Task 4.2: Apply authorization mechanisms（認可メカニズムの適用）**
  - マネージドポリシーで不足する場合のカスタムIAMポリシー作成・最小権限の原則を満たすポリシー構成
  - アプリ/DB認証情報の保管（Secrets Manager・Systems Manager Parameter Store）
  - DBユーザー/グループ/ロールへのアクセス権付与（Redshift）
  - Lake Formationによるアクセス許可管理（Redshift・EMR・Athena・S3）
  - ロールベース・タグベース・属性ベースの認可方法

- **Task 4.3: Ensure data encryption and masking（データの暗号化とマスキング）**
  - コンプライアンス法・企業ポリシーに従うデータマスキングと匿名化
  - 暗号化キーによるデータの暗号化/復号（KMS）
  - AWSアカウントの境界を越えた暗号化設定
  - 転送中または転送前の暗号化の有効化

- **Task 4.4: Prepare logs for audit（監査用ログの準備）**
  - CloudTrailによるAPIコール追跡・CloudWatch Logsによるアプリケーションログ保存
  - CloudTrail Lakeによる一元化されたログのクエリ
  - ログ分析（Athena・CloudWatch Logs Insights・OpenSearch Service）
  - 大容量ログデータ処理のためのサービス統合（EMR）

- **Task 4.5: Understand data privacy and governance（データプライバシーとガバナンスの理解）**
  - データ共有のアクセス許可付与（Redshiftデータ共有）
  - PII識別の実装（Macie + Lake Formation）
  - 許可されていないリージョンへのバックアップ/レプリケーションを防ぐデータプライバシー戦略・データ主権の維持
  - アカウントの設定変更の表示（AWS Config）
  - SageMaker Catalog プロジェクトを通じたデータアクセス管理
  - ガバナンスデータフレームワークとデータ共有パターン

■ 出題範囲の主要サービス（公式の対象サービス一覧に基づく。一覧は網羅的ではなく変更されうる）
- 分析: Athena, EMR, Glue, Glue DataBrew, Lake Formation, Kinesis Data Firehose, Kinesis Data Streams, Amazon Managed Service for Apache Flink, MSK, OpenSearch Service, Amazon Quick（旧QuickSight）, SageMaker AI
- アプリケーション統合: AppFlow, EventBridge, MWAA (Airflow), SNS, SQS, Step Functions
- コンピューティング/コンテナ: AWS Batch, EC2, Lambda, AWS SAM, ECR, ECS, EKS
- データベース: Redshift, DynamoDB, RDS, Aurora, DocumentDB, MemoryDB for Redis, Keyspaces, Neptune
- ストレージ: S3, S3 Tables, S3 Glacier, EBS, EFS, AWS Backup
- 移行と転送: DMS, DataSync, Snow Family, Transfer Family, Application Discovery Service, Application Migration Service
- 開発ツール: AWS CLI, CloudFormation, AWS CDK, CodeBuild, CodeDeploy, CodePipeline, Amazon Q
- 管理/ガバナンス: CloudTrail, CloudWatch, CloudWatch Logs, Config, Systems Manager, Managed Grafana, Well-Architected Tool, AWS Data Exchange
- セキュリティ: IAM, KMS, Macie, Secrets Manager, Shield, WAF（CloudTrail Lake・Parameter Store もタスク文に登場）
- ネットワーク: VPC, PrivateLink, CloudFront, Route 53, API Gateway
- コスト管理: AWS Budgets, Cost Explorer
- 機械学習（データ基盤の文脈に限る）: Bedrock（ナレッジベース/ベクトル化）, Kendra, SageMaker Unified Studio, SageMaker Catalog, SageMaker ML Lineage Tracking, SageMaker Data Wrangler
- データ形式/モデル: Apache Iceberg（オープンテーブルフォーマット）, ベクトルインデックス（HNSW・IVF）

■ 汎用知識の定義暗記を避ける（AWSシナリオ必須）
- JDBC/ODBCの用途、SQLのUNION=重複排除、PostgreSQLのREINDEX/VACUUM/CLUSTER/ANALYZE等の汎用DBコマンドの役割を、名称連想だけで解ける定義暗記として単体で問わない。必ずAWSサービス固有のシナリオ・複数要件の取捨選択に組み込む
- 同一テーマ・同一コマンド群で複数問を作らない（問題間のテーマ重複を避ける）
