あなたはAWS認定試験の問題作成者です。
AWS Certified Advanced Networking – Specialty (ANS-C01) の模擬試験問題を作成してください。

【難易度】
- Specialty レベル：AWSおよびハイブリッドネットワークの高度な設計・実装・トラブルシューティング
- BGP、MPLS、Direct Connect、Transit Gatewayなどの複雑なネットワーク構成を問う
- スケールと可用性を考慮したネットワーク設計の判断力を重視

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 複雑なネットワーク構成シナリオや要件定義ベースの問題を出題する
- AWSの正式サービス名を使用する
- 選択肢は紛らわしくなるよう類似サービスや設定を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・概念を優先すること

【選択肢の構成（4択・必須）】
4択は「2案ペア × 2組」の構造にすること。
- A・B : ネットワーク構成/サービスXを使う2案（BGP設定・帯域・冗長構成等が異なる）
- C・D : ネットワーク構成/サービスYを使う2案（BGP設定・帯域・冗長構成等が異なる）
→「どちらのアーキテクチャが正解か」に加え「その構成のどのパラメータが正しいか」の2段階判断を強制する。
→ 例: A・B = Transit Gateway の2ルーティング設定案、C・D = Direct Connect Gateway の2接続案
→ 全4選択肢が同一サービスでも可。その場合はBGPコミュニティ値・ECMP設定・AS-PATH等の差を細かくする。
→ 複数正解問題も同様に2〜3アプローチを2案ずつペア化する。
→ 正解と不正解の文字数・語調を揃え、ペアの形からメタ的に正解を特定できないようにする。

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 150〜400字（ネットワーク構成・帯域・冗長性要件を詳述）
- 選択肢（choices）: 各40〜100字（ネットワーク設定と具体的な構成を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス（EC2-Classic等）
- 過度に詳細なAPIパラメータ
- 正解が自明すぎる問題

【公式試験ガイド概要 (ANS-C01)】
■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：ネットワーク設計】（30%）
- Task 1.1: グローバルアーキテクチャ向けにユーザーパフォーマンスとトラフィック管理を最適化するためにエッジネットワークサービスを組み込んだソリューションを設計する（CloudFront・Global Accelerator・ELB・API Gateway との統合・インバウンド/アウトバウンドグローバルトラフィック要件の評価）
- Task 1.2: パブリック、プライベート、ハイブリッドの要件を満たす DNS ソリューションを設計する（Route 53 エイリアスレコード・トラフィックポリシー・Resolver エンドポイント・ヘルスチェック・DNSSEC・プライベートホストゾーン・条件付き転送・ドメイン登録・ハイブリッド/マルチアカウント/マルチリージョン統合）
- Task 1.3: 高可用性、スケーラビリティ、セキュリティ要件を満たすようにロードバランシングを統合するソリューションを設計する（ALB・NLB・GLB・OSI L3/L4/L7 ロードバランシング・クロスゾーン負荷分散・スティッキーセッション・ルーティングアルゴリズム・TLS終端/パススルー・ACM・EKS 用 AWS Load Balancer Controller・WAF/CloudFront/Global Accelerator/Route 53 との統合・プロキシプロトコル・GENEVE・オートスケーリング連携）
- Task 1.4: AWS とハイブリッドネットワーク全体でログ記録とモニタリングの要件を定義する（CloudWatch メトリクス/エージェント/ログ/アラーム/ダッシュボード・Transit Gateway Network Manager・VPC Reachability Analyzer・VPC Flow Logs・Traffic Mirroring・ロードバランサー/CloudFront アクセスログ・ネットワークステータス可視化メトリクスの選定・ベースライン性能の取得）
- Task 1.5: オンプレミスネットワークと AWS クラウド間のルーティング戦略と接続アーキテクチャを設計する（スタティック/ダイナミックルーティング・BGP・VLAN・LAG・ジャンボフレーム・GRE・IPsec・AWS RAM・Direct Connect・Site-to-Site VPN・オーバーレイネットワーク・SD-WAN / Transit Gateway Connect 統合・BGP 属性によるトラフィックエンジニアリング・冗長ハイブリッド接続モデル設計）
- Task 1.6: さまざまな接続パターンをサポートするために複数の AWS アカウント、リージョン、VPC を含むルーティング戦略と接続アーキテクチャを設計する（VPC ピアリング・Transit Gateway・PrivateLink・Shared VPC・AWS RAM・IP CIDR 重複対策・NAT・Transit Gateway ルーティングによる IP 重複管理）

【第2ドメイン：ネットワーク実装】（26%）
- Task 2.1: オンプレミスネットワークと AWS クラウドの間にルーティングと接続を実装する（スタティック/ダイナミックルーティングプロトコル・Site-to-Site VPN（アクセラレート VPN 含む）・Client VPN・Layer 1 物理要件（LOA）・VLAN/IP アドレッシング/ゲートウェイ/ルーティング/スイッチング・SD-WAN / Transit Gateway Connect・DNS 条件付き転送/ホストゾーン/Resolver・セキュリティアプライアンス/ファイアウォール・ロードバランシング実装（L3/L4/L7・リバースプロキシ）・CloudFormation/CDK 自動化・AWS Organizations/AWS RAM（マルチアカウント Transit Gateway・Direct Connect・VPC・Route 53）・Route Analyzer/Reachability Analyzer による接続検証）
- Task 2.2: 複数の AWS アカウント、リージョン、VPC にルーティングと接続を実装する（VPC ピアリング・Transit Gateway・PrivateLink・VPN・SD-WAN・MPLS・AWS RAM・AWS Organizations・Shared VPC・DHCP・Security Groups・NACLs・Network Firewall・SAML/Active Directory 認証・Transit VPC・ハブアンドスポーク構成・Route Analyzer/Reachability Analyzer による検証・ログ記録/モニタリング設定）
- Task 2.3: 複雑なハイブリッドおよびマルチアカウント DNS アーキテクチャを実装する（Route 53 パブリック/プライベートホストゾーン・DNS 委任・条件付き転送・DNS レコードタイプ（A/AAAA/TXT/PTR/CNAME/エイリアス）・DNSSEC・AWS RAM によるゾーン共有・Resolver インバウンド/アウトバウンドエンドポイント・トラフィック管理ポリシー（レイテンシー・地理・重み付け）・DNS モニタリングとログ記録・集中/分散ネットワークアーキテクチャ内の DNS 設定）
- Task 2.4: ネットワークインフラストラクチャを自動化して構成する（CloudFormation・CDK・AWS CLI・SDK・API・イベント駆動型ネットワーク自動化・IaC テンプレートのハードコード回避・コスト最小化・ネットワークリソース最適化の自動化・サードパーティベンダーとのハイブリッド自動化統合）

【第3ドメイン：ネットワークの管理と運用】（20%）
- Task 3.1: AWS とハイブリッドネットワークでルーティングと接続性を維持する（Direct Connect 経由 BGP・Direct Connect Gateway・Transit Gateway・VIF 種別・PrivateLink・VPC ピアリング・帯域幅/ルート数クォータへの対応・ルートテーブル管理（自動伝播・BGP）・スタティック/ダイナミックルーティング最適化（ルート集約・CIDR 重複）・リージョン間/リージョン内通信パターン・AWS サービスへのプライベート/パブリックアクセス設定）
- Task 3.2: ネットワークトラフィックをモニタリングおよび分析して、接続パターンのトラブルシューティングと最適化を行う（CloudWatch メトリクス/ログ・VPC Flow Logs・VPC Traffic Mirroring・Reachability Analyzer・Transit Gateway Network Manager・パケット損失/ルーティング問題分析・MTU/パケットサイズ不一致トラブルシューティング・パケットシェーピング分析・接続意図検証の自動化・ネットワークトポロジマッピング）
- Task 3.3: AWS ネットワークを最適化してパフォーマンス、信頼性、費用対効果を高める（VPC ピアリング vs Transit Gateway の選択・ユニキャスト vs マルチキャストによる帯域幅削減・データ転送コスト最適化・ENI/ENA/EFA ネットワークインターフェイス選択（EFA: Elastic Fabric Adapter）・SR-IOV・ECMP・ジャンボフレーム設定・マルチキャスト実装・Global Accelerator・Route 53 ヘルスチェック・サブネット最適化・セカンダリ CIDR による IP 枯渇防止・IPAM）

【第4ドメイン：ネットワークセキュリティ、コンプライアンス、ガバナンス】（24%）
- Task 4.1: セキュリティとコンプライアンスのニーズと要件を満たすためにネットワーク機能を実装し、保守する（AWS WAF・Shield・Network Firewall・Gateway Load Balancer（セキュリティアプライアンス挿入）・Security Groups・NACLs・VPC エンドポイントポリシー・Firewall Manager・インバウンド/アウトバウンドトラフィック保護・境界 VPC・3 層アーキテクチャ・非信頼ネットワーク設計・脅威モデルと緩和戦略・フェイルオーバーテスト・セキュリティアラートの自動化）
- Task 4.2: ネットワークのモニタリングおよびログ記録サービスを使用してセキュリティを検証し、監査する（CloudWatch メトリクス/カスタムメトリクス/アラーム・CloudTrail・VPC Flow Logs（ベースフィールド/拡張フィールド）・VPC Traffic Mirroring・Transit Gateway Network Manager・Amazon Kinesis によるログ配信・Firewall Manager・Trusted Advisor・ネットワークセキュリティ設定の監査（Security Groups/NACLs）・マルチアカウント横断ネットワーク監査戦略・ログ配信ソリューション実装）
- Task 4.3: ネットワークのデータと通信の機密性を実装し、保守する（IPsec・TLS（終端/パススルー）・Direct Connect 経由 VPN・転送中データ暗号化（CloudFront/ALB/NLB/Transit Gateway/AWS マネージドデータベース/S3/EC2 カスタム）・ACM による証明書管理・DNSSEC によるセキュア DNS 通信・AWS 責任共有モデル下のネットワーク暗号化）
