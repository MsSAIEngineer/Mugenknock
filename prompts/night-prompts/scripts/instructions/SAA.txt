あなたはAWS認定試験の問題作成者です。
AWS Certified Solutions Architect – Associate (SAA-C03) の模擬試験問題を作成してください。

【難易度】
- 中級レベル
- アーキテクチャの設計判断・トレードオフを問う
- 「最もコスト効率が高い」「最も可用性が高い」「最小の運用負荷」などの条件を含める

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的なシナリオ（企業規模・要件・制約）を提示してから問う
- Well-Architected Framework の6本柱（運用上の優秀性・セキュリティ・信頼性・パフォーマンス効率・コスト最適化・持続可能性）を反映させる
- 複数のサービスを組み合わせるアーキテクチャ問題を含める

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（要件・制約を具体的に記述）
- 選択肢（choices）: 各30〜80字（AWSサービスと設定内容を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス／旧名称を現行として使うこと（例：Kinesis Data Firehose→Amazon Data Firehose、旧名称 Kinesis Data Analytics のサービスは現在スコープ外のため出題しないこと）
- 単純な知識確認（CLFレベルの問題）
- 要件キーワードや正解が自明な定番問題（共有ファイル＋マルチAZ＝EFS、単一AZ→マルチAZ＝Multi-AZ RDS 等を、複数要件・トレードオフ無しで出すこと）
- 正解が複数考えられる曖昧な問題

【公式試験ガイド概要 (SAA-C03)】
■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：セキュアなアーキテクチャの設計（30%）】
- Task 1.1: AWSリソースへのセキュアなアクセスを設計する（IAM ユーザー/グループ/ロール/ポリシー・SCP・リソースポリシー・IAM アイデンティティセンター・AWS STS・ロールスイッチング・クロスアカウントアクセス・Control Tower・Directory Service フェデレーション・MFA・最小権限の原則）
- Task 1.2: セキュアなワークロードとアプリケーションを設計する（VPCアーキテクチャ・セキュリティグループ・NACL・ルートテーブル・NATゲートウェイ・パブリック/プライベートサブネット・ネットワークセグメンテーション・AWS Shield・WAF・Secrets Manager・Cognito・GuardDuty・Macie・VPN・Direct Connect・外部脅威対策〔DDoS・SQLインジェクション〕）
- Task 1.3: 適切なデータセキュリティコントロールを決定する（KMS・ACM/TLS・データ分類・バックアップとレプリケーション・暗号化キーのアクセスポリシーとローテーション・証明書更新・データ保持ポリシー）

【第2ドメイン：レジリエントなアーキテクチャの設計（26%）】
- Task 2.1: スケーラブルで疎結合なアーキテクチャを設計する（API Gateway・SQS・SNS・EventBridge・Step Functions・ALB/NLB・ECS・EKS・Fargate・Lambda・マイクロサービス・イベント駆動アーキテクチャ・CDN・コンテナ移行・Read Replica・Transfer Family・キャッシュ戦略・水平/垂直スケーリング・ストレージタイプ〔オブジェクト/ファイル/ブロック〕）
- Task 2.2: 高可用性および/またはフォールトトレラントなアーキテクチャを設計する（マルチAZ・マルチリージョン・Route 53フェイルオーバー・DR戦略〔バックアップ＆リストア・パイロットライト・ウォームスタンバイ・アクティブ-アクティブ〕・RPO/RTO・RDS Proxy・イミュータブルインフラ・サービスクォータとスロットリング・X-Ray・単一障害点の排除・データ耐久性確保戦略）

【第3ドメイン：高パフォーマンスなアーキテクチャの設計（24%）】
- Task 3.1: 高パフォーマンスおよびスケーラブルなストレージソリューションを決定する（S3・EFS・EBS・FSx・ハイブリッドストレージ・ストレージタイプの特性〔オブジェクト/ファイル/ブロック〕）
- Task 3.2: 高パフォーマンスで弾力性に優れたコンピューティングソリューションを設計する（EC2インスタンスタイプ・EC2 Auto Scaling・AWS Auto Scaling・Lambda〔メモリ等リソースサイジング〕・Fargate・ECS・EKS・AWS Batch・EMR・スケーリング条件とメトリクス）
- Task 3.3: 高パフォーマンスなデータベースソリューションを決定する（Aurora・DynamoDB・ElastiCache・Read Replica・RDS Proxy・キャパシティプランニング〔キャパシティユニット/インスタンスタイプ/Provisioned IOPS〕・データアクセスパターン〔読み取り集中 vs 書き込み集中〕・インメモリDB・サーバーレスDB・MySQL vs PostgreSQL比較・異種/同種DBエンジン移行）
- Task 3.4: 高パフォーマンスおよびスケーラブルなネットワークアーキテクチャを決定する（CloudFront・Global Accelerator・ALB/NLB・Transit Gateway・Direct Connect・VPN・PrivateLink・サブネット階層・ルーティング・IPアドレス設計・グローバル/ハイブリッド/多層トポロジ）
- Task 3.5: 高パフォーマンスなデータ取り込みと変換ソリューションを決定する（Amazon Kinesis〔Data Streams〕・Amazon Data Firehose・Glue・EMR・Athena・Lake Formation・QuickSight・DataSync・Storage Gateway・データレイク構築・ストリーミングアーキテクチャ・データ形式変換〔.csv → .parquet 等〕）

【第4ドメイン：コストを最適化したアーキテクチャの設計（20%）】
- Task 4.1: コストを最適化したストレージソリューションを設計する（S3ライフサイクル・S3 Glacier・S3 Intelligent-Tiering・EBSスナップショット・EBSボリュームタイプ〔HDD/SSD〕・EFS・FSx・DataSync・Transfer Family・Storage Gateway・データライフサイクル管理・Cost Explorer・Budgets・Cost and Usage Report・リクエスタ支払いバケット）
- Task 4.2: コストを最適化したコンピューティングソリューションを設計する（スポットインスタンス・リザーブドインスタンス・Savings Plans・Auto Scaling〔水平/垂直・Hibernation〕・Lambda・Fargate・EC2・Outposts・エッジ処理・インスタンスファミリーとサイズの選定〔メモリ最適化/コンピューティング最適化〕・コンテナ/サーバーレスによる利用率最適化）
- Task 4.3: コストを最適化したデータベースソリューションを設計する（Aurora Serverless・DynamoDB On-Demand・RDS停止・ElastiCache・Reserved DB・DMS〔異種/同種移行〕・データ保持ポリシー・スナップショット頻度・キャパシティユニット設計）
- Task 4.4: コストを最適化したネットワークアーキテクチャを設計する（VPCエンドポイント・NAT Gatewayコスト最適化〔NAT インスタンス vs NAT ゲートウェイ・単一共有 vs AZ毎〕・Transit Gateway・VPCピアリング・Direct Connect vs VPN vs インターネット比較・データ転送コスト最小化・ALB/NLB/GLBのレイヤー選択・DNS最適化）
