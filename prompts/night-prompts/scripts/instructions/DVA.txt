あなたはAWS認定試験の問題作成者です。
AWS Certified Developer – Associate (DVA-C02) の模擬試験問題を作成してください。

【難易度】
- Associate レベル：AWSサービスを使ったアプリケーション開発・デプロイ・デバッグの実践的な知識
- AWS SDK、CLI、APIを使った開発スキルを問う
- サーバーレス・コンテナ・CI/CD パイプラインなどの実装を重視

【問題スタイル】
- 4択（単一正解）を基本とし、または5択から2択の複数正解
- 具体的な開発・デプロイシナリオを提示してから問う
- 「最も効率的」「最小限の変更」「最もスケーラブル」などのトレードオフを含める
- 複数のAWSサービスを組み合わせるアーキテクチャ問題を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先して出題すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（コード構成・要件・エラー内容を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な設定・操作を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス
- CLFレベルの単純なサービス説明問題
- 正解が複数考えられる曖昧な問題

---
【公式試験ガイド概要 (DVA-C02)】
■ 出題ドメインと配点
- コンテンツ分野 1: AWSのサービスによる開発 (32%)
- コンテンツ分野 2: セキュリティ (26%)
- コンテンツ分野 3: デプロイ (24%)
- コンテンツ分野 4: トラブルシューティングと最適化 (18%)

■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：AWSのサービスによる開発 (32%)】
- Task 1.1: AWSでホストされているアプリケーション用のコードを開発する
  - アーキテクチャパターン（イベント駆動型・マイクロサービス・モノリシック・コレオグラフィー・オーケストレーション・ファンアウト等）の説明と選択
  - ステートフルとステートレスの概念の違いの説明と設計選択
  - 密結合と疎結合コンポーネントの違いの説明
  - 同期パターンと非同期パターンの違いの説明
  - レジリエントなアプリケーション作成（再試行ロジック・サーキットブレーカー・エラー処理パターン等）
  - APIの作成・拡張・保守（レスポンス/リクエスト変換・検証ルール・ステータスコードオーバーライド等）
  - メッセージングサービスを使用するためのコード記述
  - AWS SDK・APIを使ってAWSサービスとやり取りするコード記述
  - ストリーミングデータの処理
  - Amazon Q Developerを使用した開発支援
  - Amazon EventBridgeを使用したイベント駆動型パターンの実装

- Task 1.2: AWS Lambda用のコードを開発する
  - LambdaコードからのVPC内プライベートリソースへのアクセス
  - 環境変数とパラメータ（メモリ・同時実行・タイムアウト・ランタイム・ハンドラー・レイヤー・拡張機能・トリガー・送信先等）によるLambda関数の設定
  - コードを使用したイベントライフサイクルとエラー処理（Lambda送信先・デッドレターキュー等）
  - Lambda関数とAWSサービスの統合
  - 最適パフォーマンスのためのLambda関数チューニング
  - Lambda関数を使用したほぼリアルタイムのデータ処理と変換

- Task 1.3: アプリケーション開発でデータストアを使用する
  - バランスの取れたパーティションアクセスのための高カーディナリティパーティションキーの説明
  - データベース整合性モデル（強整合性・結果整合性等）の説明と選択
  - クエリオペレーションとスキャンオペレーションの違いの説明
  - Amazon DynamoDBキーとインデックス（GSI/LSI）の定義
  - データのシリアル化・逆シリアル化とデータストアへの永続化
  - データストア（DynamoDB・ElastiCache・DAX等）の使用・管理・保守
  - データライフサイクルの管理
  - データキャッシュサービスの使用
  - アクセスパターンに基づく専用データストアの選択（Amazon OpenSearch Service等）

【第2ドメイン：セキュリティ (26%)】
- Task 2.1: アプリケーションとAWSサービスの認証および/または認可を実装する
  - IDプロバイダーを使用したフェデレーテッドアクセスの実装（Amazon Cognito・IAM等）
  - ベアラートークンを使用したアプリケーションのセキュリティ保護
  - AWSへのプログラムによるアクセスの設定
  - AWSサービスに対する認証済み呼び出しの実行
  - IAMロールの引き受け（AssumeRole）
  - IAMプリンシパルのアクセス許可の定義
  - きめ細かいアクセスコントロールのためのアプリケーションレベル認可の実装
  - マイクロサービスアーキテクチャにおけるクロスサービス認証の処理

- Task 2.2: AWSサービスを使用した暗号化を実装する
  - 保管中と転送中の暗号化の定義と実装
  - 証明書管理の説明（AWS Private CA等）
  - クライアント側暗号化とサーバー側暗号化の違いの説明
  - 暗号化キー（KMS CMK・エンベロープ暗号化等）を使用したデータの暗号化/復号
  - 開発目的での証明書とSSHキーの生成
  - アカウントの境界を越えた暗号化の使用
  - キーローテーションの有効化/無効化

- Task 2.3: アプリケーションコードで機密データを管理する
  - データ分類の説明（PII・PHI等）
  - 機密データを含む環境変数の暗号化
  - シークレット管理サービスを使用した機密データの保護（Secrets Manager・SSM Parameter Store SecureString等）
  - 機密データのサニタイズ
  - アプリケーションレベルのデータマスキングとサニタイズの実装
  - マルチテナントアプリケーションのデータアクセスパターンの実装

【第3ドメイン：デプロイ (24%)】
- Task 3.1: AWSにデプロイするアプリケーションアーティファクトを準備する
  - パッケージ内のコードモジュール依存関係の管理（環境変数・設定ファイル・コンテナイメージ等）
  - アプリケーションデプロイのためのファイルとディレクトリ構造の整理
  - デプロイ環境でのコードリポジトリの使用
  - リソース（メモリ・コア等）へのアプリケーション要件の適用
  - 特定環境向けのアプリケーション構成の準備（AWS AppConfigの使用等）

- Task 3.2: 開発環境でアプリケーションをテストする
  - AWSのサービスとツールを使用したデプロイ済みコードのテスト
  - 外部依存関係用の統合テストとモックAPIの作成
  - 開発エンドポイントを使用したアプリケーションのテスト（API GatewayでのステージのSet up等）
  - 既存の環境へのアプリケーションスタック更新のデプロイ（SAMテンプレートを別のステージング環境にデプロイ等）
  - イベント駆動型アプリケーションのテスト

- Task 3.3: デプロイテストを自動化する
  - アプリケーションテストイベントの作成（Lambda・API Gateway・SAMリソース用JSONペイロード等）
  - さまざまな環境へのAPIリソースのデプロイ
  - 統合テスト用に承認済みバージョンを使用するアプリケーション環境の作成（Lambdaエイリアス・コンテナイメージタグ・AWS Amplifyブランチ・AWS Copilot環境等）
  - IaCテンプレートの実装とデプロイ（SAMテンプレート・CloudFormationテンプレート等）
  - 個々のAWSサービスの環境管理（API Gatewayでの開発/テスト/本番環境の区別等）
  - Amazon Q Developerを使用した自動テスト生成

- Task 3.4: AWSのCI/CDサービスを使ってコードをデプロイする
  - Lambdaデプロイのパッケージングオプションの説明
  - API GatewayステージとカスタムドメインおよびLambdaエイリアスの組み合わせ
  - 既存のIaCテンプレートの更新（SAMテンプレート・CloudFormationテンプレート等）
  - AWSサービスを使用したアプリケーション環境の管理
  - デプロイ戦略を使用したアプリケーションバージョンのデプロイ
  - コードリポジトリへのコミットによるビルド・テスト・デプロイアクションの呼び出し
  - オーケストレーションされたワークフローを使用したさまざまな環境へのコードデプロイ
  - 既存のデプロイ戦略を使用したアプリケーションロールバックの実行
  - バージョンとリリース管理のためのラベルとブランチの使用
  - 既存ランタイム設定を使用した動的デプロイの作成（Lambda関数でAPI Gatewayのステージング変数を使用等）
  - アプリケーションリリースのデプロイメント戦略の設定（ブルー/グリーン・カナリア・ローリング等）

【第4ドメイン：トラブルシューティングと最適化 (18%)】
- Task 4.1: 根本原因分析を支援する
  - コードのデバッグと欠陥の特定
  - アプリケーションメトリクス・ログ・トレースの解釈
  - ログのクエリによる関連データの発見（CloudWatch Logs Insights・Amazon Athena等）
  - カスタムメトリクスの実装（CloudWatch EMF等）
  - ダッシュボードとインサイトを使用したアプリケーションヘルスの確認
  - サービス出力ログを使用したデプロイ失敗のトラブルシューティング
  - アプリケーションにおけるサービス統合の問題のデバッグ

- Task 4.2: オブザーバビリティのためのコードを考案する
  - ログ記録・モニタリング・オブザーバビリティの違いの説明
  - アプリケーションの動作と状態を記録する効果的なログ記録戦略の実装
  - カスタムメトリクスを出力するコードの実装（CloudWatch EMF等）
  - トレースサービスへの注釈の追加（X-Ray セグメント・サブセグメント・アノテーション等）
  - 特定のアクションに関する通知アラートの実装（クォータ制限・デプロイ完了通知等）
  - AWSのサービスとツールを使用したトレースの実装（X-Ray SDK等）
  - アプリケーションイベントとユーザーアクションの構造化ログ記録の実装
  - アプリケーションヘルスチェックとレディネスプローブの設定

- Task 4.3: AWSのサービスと機能を使ってアプリケーションを最適化する
  - 同時実行の定義と設定（Lambdaプロビジョニング済み同時実行・予約済み同時実行等）
  - アプリケーションのパフォーマンスのプロファイリング（Lambda Power Tuning等）
  - アプリケーションの最小メモリと処理能力の判断
  - サブスクリプションフィルターポリシーを使用したメッセージの最適化（SNSフィルタリング等）
  - リクエストヘッダーに基づくコンテンツキャッシュの設定
  - アプリケーションレベルのキャッシュの実装によるパフォーマンス向上（ElastiCache・DAX・SQSロングポーリング等）
  - アプリケーションリソース使用の最適化
  - アプリケーションのパフォーマンス問題の分析
  - アプリケーションログを使用したパフォーマンスボトルネックの特定

■ 出題範囲の主要サービスと概念（公式スコープ内 65サービス）
- 分析: Amazon Athena, Amazon Kinesis, Amazon OpenSearch Service
- アプリケーション統合: AWS AppSync, Amazon EventBridge, Amazon SNS, Amazon SQS, AWS Step Functions
- コンピューティング: Amazon EC2, AWS Elastic Beanstalk, AWS Lambda（関数・レイヤー・拡張機能・コンカレンシー・デスティネーション・VPCアクセス・コンテナイメージ）
- コンテナ: Amazon ECR, Amazon ECS（タスク定義・サービス）, Amazon EKS, AWS Fargate
- データベース: Amazon Aurora, Amazon DynamoDB（パーティションキー設計・GSI・LSI・トランザクション・Streams）, Amazon ElastiCache, Amazon RDS, Amazon DAX
- デベロッパーツール: AWS Amplify, AWS CloudShell, AWS CodeArtifact, AWS CodeBuild, AWS CodeDeploy（デプロイ戦略・AppSpec）, AWS CodePipeline, AWS X-Ray, Amazon Q Developer
- マネジメントとガバナンス: AWS AppConfig, AWS CDK, AWS CloudFormation, AWS CloudTrail, Amazon CloudWatch（メトリクス・ログ・EMF・アラーム・ダッシュボード）, AWS CLI, AWS Systems Manager
- ネットワークとコンテンツ配信: Amazon API Gateway（REST/HTTP・オーソライザー・使用量プラン・スロットリング・CORS・カスタムドメイン・ステージ変数）, Amazon CloudFront, Elastic Load Balancing, Amazon Route 53, Amazon VPC
- セキュリティ・アイデンティティ・コンプライアンス: Amazon Cognito（User Pools・Identity Pools・JWT）, AWS IAM（ロール・AssumeRole）, AWS KMS（CMK・エンベロープ暗号化・キーローテーション）, AWS Secrets Manager, AWS STS, AWS WAF, AWS Private CA
- ストレージ: Amazon EBS, Amazon EFS, Amazon S3（署名付きURL・イベント通知・マルチパートアップロード）

- SDK・API: AWS SDK（認証情報プロバイダーチェーン）, AWS SAM
