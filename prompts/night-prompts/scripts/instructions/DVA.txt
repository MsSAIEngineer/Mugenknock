# LAST_REFRESHED: 2026-10-28


あなたはAWS認定試験の問題作成者です。
AWS Certified Developer – Associate (DVA-C03) の模擬試験問題を作成してください。
（注：DVA-C03 は 2026-12-01 から受験登録開始。旧版 DVA-C02 の受験最終日は 2026-11-30。出典: AWS 公式試験ガイド developer-associate-03）

【難易度】
- Associate レベル：AWSサービスを使ったアプリケーション開発・テスト・デプロイ・デバッグの実践的な知識（AI支援開発ツールの活用を含む）
- AWS SDK、CLI、APIを使った開発スキルを問う
- サーバーレス・コンテナ・CI/CD パイプラインなどの実装を重視
- 対象は実務経験1年以上の開発者。アーキテクチャ設計、CI/CDパイプラインの設計・作成、IAMユーザー/グループの管理、サーバー/OS管理、FM選定・プロンプト設計・RAG設計、AIセーフティ/ガバナンス設計、ETLパイプライン設計、ネットワークインフラ設計は範囲外

【問題スタイル】
- 4択（単一正解）を基本とし、または5択以上から2つ以上の複数正解
- 具体的な開発・デプロイシナリオを提示してから問う
- 「最も効率的」「最小限の変更」「最もスケーラブル」などのトレードオフを含める
- 複数のAWSサービスを組み合わせる問題を含める
- プロンプト末尾の【現在のドメイン別問題数】は参考情報。まだカバーが薄いサービス・ユースケースを優先して出題すること

【問題文・選択肢の目安文字数】
- 問題文（questionText）: 100〜300字（コード構成・要件・エラー内容を具体的に記述）
- 選択肢（choices）: 各30〜80字（サービス名と具体的な設定・操作を明示）

【避けること】
- 正解の選択肢の文字数が不正解の選択肢群から浮かないようにすること（正解の文字数を不正解の平均文字数に近づけること）
- 廃止・非推奨のサービス
- CLFレベルの単純なサービス説明問題
- 正解が複数考えられる曖昧な問題

---
【公式試験ガイド概要 (DVA-C03)】
■ 出題ドメインと配点（スコア対象問題50問＋採点対象外15問、合格スコア720/1000）
- コンテンツ分野 1: AWSのサービスによる開発 (30%)
- コンテンツ分野 2: セキュリティ (26%)
- コンテンツ分野 3: テストとデプロイ (22%)
- コンテンツ分野 4: トラブルシューティングと最適化 (22%)

■ 公式タスク文（出題で必ずカバーすること）

【第1ドメイン：AWSのサービスによる開発 (30%)】
- Task 1.1: AWSでホストされているアプリケーション用のコードを開発する
  - 密結合・疎結合システムの識別と、AWSサービスによるコンポーネントの疎結合化
  - 同期パターンと非同期パターンの選択（API Gatewayの同期呼び出し、SQSによる非同期処理、EventBridgeのイベント駆動ワークフロー等）
  - フォールトトレラントでレジリエントなアプリケーションの作成・保守（バックオフ付き再試行、グレースフルデグラデーション等）
  - APIの作成・拡張・保守（リクエスト/レスポンス変換、検証ルールの適用等）
  - APIとAWS SDKを使ってAWSサービスとやり取りするコードの開発
  - AWSサービスによるストリーミングデータの管理
  - データのシリアル化・逆シリアル化によるアプリケーションコードとAWSサービスの統合
  - イベント駆動パターンの実装（EventBridge、S3イベント通知、SQS、SNS等）
  - AI支援開発ツールによるコードの生成・レビュー・最適化（仕様駆動のコード生成、自動コードレビュー、コード補完、リファクタリング提案、セキュリティスキャン等）
  - マネージドAWS AIサービスのアプリケーションへの統合

- Task 1.2: AWS Lambda用のコードを開発する
  - LambdaからVPC内のプライベートリソースへのアクセス許可
  - 環境変数とパラメータ（メモリ・同時実行・タイムアウト・ランタイム・ハンドラー・レイヤー・拡張機能）によるLambda関数の設定
  - イベントライフサイクルとエラー処理（Lambda送信先・デッドレターキュー等）
  - コード、イベントソースマッピング、送信先によるLambdaとAWSサービスの統合（API Gateway、DynamoDB等）

- Task 1.3: アプリケーション開発でデータストアを使用する
  - データライフサイクルの管理（S3ライフサイクルポリシー、TTL、保持期間等）
  - アクセスパターンに基づくデータストアの選択（ElastiCache・DynamoDB・S3・RDS等）
  - データストアの選択に応じた適切なキャッシュソリューションの判断
  - DynamoDBの構成（高カーディナリティのパーティションキー、読み取り整合性モデル、クエリ/スキャン操作、キー・属性・インデックス（GSI/LSI）の定義）

【第2ドメイン：セキュリティ (26%)】
- Task 2.1: アプリケーションとAWSサービスの認証・認可メカニズムを実装する
  - IDフェデレーションの実装
  - アクセスコントロールの実装（きめ細かいアクセス許可、セキュリティトークン、MFA）
  - AWSへのプログラムによるアクセスの設定
  - 署名付きURLによる安全で期限付きのアクセス提供（S3、CloudFront）
  - AWSサービスへの認証済み呼び出し
  - IAMプリンシパル（ユーザー・ロール・サービス）とリソースのアクセス許可の定義
  - IAMロールの引き受け（AssumeRole）

- Task 2.2: AWSサービスを使って暗号化を実装し、機密データを管理する
  - 保管中と転送中の暗号化の適用
  - 証明書管理（AWS Certificate Manager、AWS Private CA）
  - クライアント側暗号化とサーバー側暗号化の選択と適用
  - 暗号化キーによるデータの暗号化/復号
  - 開発目的での証明書とSSHキーの生成
  - 機密データ（PII・PHI等）の識別・マスク・アクセス制限
  - シークレット管理サービス（Secrets Manager、SSM Parameter Store等）による機密データの保護

- Task 2.3: AIサービスの利用・統合に伴うセキュリティリスクを特定し軽減する（DVA-C03 新設）
  - AIサービスへのアクセスのリクエストと管理
  - AIサービスへのデータ送信時のプライバシー制御（VPCエンドポイントによるプライベート接続、入出力がモデル学習に使われないことの確保）
  - AIモデルの入出力のフィルタリングと制御（コンテンツフィルタリング、機密情報検出、PII/PHIの編集、拒否トピックポリシー、プロンプトインジェクション対策）
  - AIエージェントのやり取りの保護（ツール使用の認可、セッション分離、機密操作のヒューマンインザループ承認）
  - AIサービス利用時のモニタリングログ内の機密コンテンツの保護

【第3ドメイン：テストとデプロイ (22%)】
- Task 3.1: AWSにデプロイするアプリケーションアーティファクトを準備する
  - パッケージ内のコードモジュール依存関係の管理（環境変数・設定ファイル・コンテナイメージ）
  - コンテナイメージのビルドと管理（ECR、Dockerfile、イメージタグ付け、ライフサイクルポリシー）
  - デプロイ環境でのコードリポジトリの使用
  - 環境固有のアプリケーション構成の管理（AWS AppConfig、SSM Parameter Store、Secrets Manager、API Gateway、Lambda）
  - API Gatewayの機能とリソース（ステージ固有のURL、エンドポイント）の利用

- Task 3.2: AWS環境でアプリケーションテストを実装し自動化する
  - テストの開発と検証（AWS SAM、AWS CDK、AWS CloudFormation）
  - 外部依存関係用のモックAPI（API Gateway等）の利用
  - アプリケーションテストイベントの作成（Lambda・API Gateway用JSONペイロード）
  - アプリケーション環境の作成と構成（Lambdaエイリアス、コンテナイメージタグ、Amplifyブランチ、AWS Copilot環境、API Gateway API）
  - AWS AIツールによるテスト生成と反復的なテストワークフローの自動化（テスト実行、結果分析、回帰テスト、カバレッジ）

- Task 3.3: AWSのCI/CDサービスを使ってコードをデプロイする
  - Lambdaのデプロイパッケージング方法（.zip、コンテナイメージ、レイヤー）によるデプロイ効率の最適化
  - コンテナオーケストレーションサービスによるコンテナ化アプリのデプロイ（ECSタスク定義、EKSマニフェスト、Fargate起動タイプ、ローリング更新）
  - IaCテンプレートの利用（CloudFormation、SAM）
  - AWS CodeDeployによるアプリケーションリビジョンのデプロイ
  - AWS CodePipelineによるCI/CDパイプラインのオーケストレーション（リポジトリ連携による起動、複数環境への段階的展開）
  - デプロイ戦略の実装（ブルー/グリーン、カナリア、ローリング）
  - 自動/手動ロールバックの実装（CloudFormation、CodeDeploy）
  - ソースコントロール機能によるバージョン・リリース管理（ラベル、ブランチ）
  - AWS AIツールによるCI/CDワークフローの支援（デプロイ承認の自動化、環境プロビジョニング、デプロイ後検証）

【第4ドメイン：トラブルシューティングと最適化 (22%)】
- Task 4.1: 根本原因分析を支援する
  - アプリケーションコードとサービス統合の問題のデバッグによる欠陥の特定
  - アプリケーションのメトリクス・ログ・トレースの解釈
  - ログのクエリによる関連データの発見（CloudWatch Logs Insights、Athena等）
  - 出力ログを使ったデプロイ失敗のトラブルシューティング
  - AWS AIツールによるエラー分析とトラブルシューティング提案の生成

- Task 4.2: ロギング・モニタリング・オブザーバビリティのベストプラクティスを適用する
  - アプリケーションの動作と状態を記録する効果的なログ戦略（イベントとユーザーアクションの構造化ログ）
  - カスタムメトリクスを出力するコードの実装（CloudWatch EMF等）
  - 特定アクションの通知アラート（クォータ制限、デプロイ完了通知）
  - AWSのサービスとツールによるトレースの実装（X-Ray等）
  - ワークロードヘルスの監視（ヘルスチェック、ライブネス/レディネスプローブ）

- Task 4.3: AWSのサービスと機能を使ってアプリケーションを最適化する
  - 同時実行の概念の適用（Lambdaプロビジョニング済み同時実行、EC2 Auto Scaling、スレッドプール管理、コネクションプーリング）
  - アプリケーションのメモリと処理能力の最適化（Lambda関数のパフォーマンスチューニング、Lambda Power Tuning等）
  - アプリケーションメッセージングの最適化（SQSキュー、SNSファンアウトパターン）
  - AWSサービスによるキャッシュの実装（ElastiCache、DAX、CloudFront）
  - パフォーマンスボトルネックの検出（CloudWatch等）
  - AWS AIツールによる最適化機会の特定（ボトルネック検出、リソース使用の最適化、コード効率の改善）
